# Bytecode patches

The mod's own coremod, `com.exiledradio.trailsandtalesbackport.asm.TrailsAndTalesCore` (sorting index 1001, so every
class arrives with SRG member names in a real instance and MCP names in dev; each patch matches both). One transformer
per patch, no MixinBooter, nothing loaded from inside a transformer. A target of another shape than expected (another
coremod got there first and changed it) is left alone and logged, so vanilla's behavior stays. Inserted code changes no
stack-map frame: no new local, and a parameter is read only on a method's first line (Mojang's unpatched classes keep
ProGuard's frames, which drop a parameter once vanilla stops reading it).

Each patch's hook checks its own config and `Presentation.isAtLeast(...)`, so with the feature off the game behaves as
1.12.2 does. `Asm.APPLIED` lists the patches the running game applied (the self-tests read it).

No local read, no branch, so no frame changes. It stacks with Nether Update's P2 (a head that returns its own discs' signals and falls through otherwise) in either order: P2's 13 for Pigstep passes through unchanged. Wild Update's P5 adds other methods to the class and is untouched. | 1.12.2 counts the jukebox's signal from the disc's item id, right for vanilla's twelve discs only; the comparator asks the block itself, and no event or registry gives a disc its signal. |

P1-P6's target classes are patched by Forge, so they are javac-built: no ProGuard frames to keep (the dev runs cover the
stack shape); P7 changes no frame either way. P1 is client-only; P2 runs on both sides; P3 changes only the client branch of its method; P4 runs on the server (integrated or dedicated); P5, P6 and P7 run on both sides (their hooks act on the server). `-Pselftest=structures` checks P7 (alone, and with
Nether Update and Wild Update in `eclipse/mods`). The self-tests check which applied (`-Pselftest=leftovers` on
the server for P2, `runClient -Pselftest=client` for P1).
